# RepoEvidence v1.1：交付、评测与索引运营设计

## 目标

将已运行的本地代码证据问答助手升级为可交付、可验证、可维护的简历项目。v1.1 覆盖三类能力：本地一键交付与 GitHub CI、仅供开发者使用的 RAG 评测、以及面向用户的索引可见性和快照治理。

## 非目标

- 不在普通问答页面加入评测题库、评测分数或模型供应商设置。
- 不运行在线模型调用作为 CI 的一部分。
- 不增加多用户、登录、云端部署或自动删除仍被会话引用的证据。
- 不允许交付脚本自动提交 `.env`、密钥、Docker 数据卷或在线模型原始回答。

## 交付流程

`make ci` 是唯一的可重复质量门禁，顺序执行后端静态检查与测试、前端格式检查/测试/构建、离线评测。它不读取模型密钥、不调用外部模型。

`make github-init` 是首次一次性初始化入口。它检查 `gh`、Git 用户身份、工作区状态和 GitHub 登录；在用户浏览器授权后创建私有仓库、设置 `origin`、推送 `main` 分支。它不替用户创建或保存令牌。

`make deliver` 先运行 `make ci`，生成脱敏交付摘要，再扫描拟提交内容。只有没有敏感文件/模式且用户明确确认后，它才创建带默认语义化消息的 Git commit 并推送至 `origin/main`。任意检查失败或推送失败都不删除本地改动。

GitHub Actions 调用 `make ci`，并以与本地一致的 Python/Node 工具链运行。在线评测只由开发者手动触发。

## 开发者 RAG 评测

离线评测复用现有 `repositories.evaluation` 的确定性评分，不调用模型或向量服务。题库以版本控制的 JSON/JSONL fixture 表达，至少涵盖模块定位、配置来源、跨文件调用、路径/行号引用和过期快照拒答。评测器输出：总例数、通过数、引用准确率、引用覆盖率、失败案例标识和运行耗时。

详细 JSON 产物写入已忽略的 `artifacts/evaluation/`；面向提交的 Markdown 摘要写入 `docs/quality/`，只包含聚合指标和失败案例 ID。`make eval` 运行离线评测；`make eval-online` 仅在用户已配置模型密钥时运行真实端到端样例，并把原始回答保留在本机工件中。

## 索引体验

仓库根目录可选 `.repoevidenceignore`。规则采用逐行 POSIX glob：空行和 `#` 注释忽略；目录规则以 `/` 结尾；不支持否定规则。扫描器仍优先执行现有的路径越界、符号链接、敏感文件、二进制文件和大小限制防护；用户规则只会额外排除，不能重新包含安全策略已排除的文件。

索引任务维护每个仓库的短生命周期进度记录，阶段为 `scanning`、`preparing`、`reusing`、`embedding`、`finalizing`、`ready` 或 `failed`。进度包含扫描文件数、忽略文件数、可复用文件数、新嵌入块数、耗时和安全错误摘要。HTTP 仓库视图返回该进度；现有前端轮询显示阶段、计数、耗时和最终复用率。

## 快照清理

清理是显式双步骤操作：先预览候选项，再由用户确认删除。候选只能是 `failed` 或 `superseded` 快照；当前 `collection_id`、任意会话创建事件中引用的 `collection_id`、以及 `building` 快照永远不可删除。删除一个候选时，同时删除其 Postgres collection 与 SQLite 注册表记录/文件清单。清理报告只暴露 collection ID、状态、创建时间和删除数量，绝不暴露宿主机绝对路径。

## 验收标准

1. 在干净的开发环境中，`make ci` 成功或以明确失败步骤退出；GitHub Actions 执行同一入口。
2. 通过 `make github-init` 的用户可以创建私有远程仓库并完成首次推送；`make deliver` 在安全预检和确认后提交、推送并生成报告。
3. 离线评测无模型密钥也能在 CI 运行，并输出聚合质量指标；在线评测不在 CI 中运行。
4. `.repoevidenceignore` 的匹配项不会进入 manifest 或嵌入；索引页面能显示准确阶段与统计。
5. 清理预览不会列出当前、构建中或会话引用快照；确认清理只删除预览允许的快照。
