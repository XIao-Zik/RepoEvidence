# RepoEvidence 面试演示脚本

建议准备一个小型、无密钥的示例仓库。演示全程约 6–8 分钟。

## 演示前检查

```bash
make up
make ps
```

确认 `.env` 中的 `REPO_EVIDENCE_ALLOWED_ROOT_PATH` 指向示例仓库的父目录；浏览器打开 `http://127.0.0.1:5173`。

若旧项目占用默认端口，使用 `.env` 中配置的 `REPO_EVIDENCE_FRONTEND_PORT` 替换上面的 `5173`；推荐为 `15173`。

## 演示流程

1. **问题与安全边界（30 秒）**

   “普通 RAG 容易把旧索引与刚改过的文件混在一起。我这里把本地仓库变成不可变证据快照，并且后端只读挂载用户明确授权的目录。”

2. **登记和索引（60–90 秒）**

   在左侧选择根目录，输入示例仓库的相对路径，点击“登记仓库”和“创建索引”。

   “浏览器没有提交绝对宿主机路径；后端只接受根 ID 和相对路径，并过滤依赖目录、二进制和高风险秘密文件。”

3. **提出一个可验证的问题（90 秒）**

   创建会话，提问：`认证失败时，处理请求的入口在哪里？请给出文件和行号。`

   展示回答中的证据和运行轨迹。

   “模型不是直接读整个仓库，而是调用受限的搜索和行范围读取工具。回答的证据带相对路径与行号，可以由人复查。”

4. **制造代码变更（60 秒）**

   在示例仓库中修改一个已索引文件，保存后回到页面点击“扫描变更”，或直接再次提问。

   “系统对当前文件清单计算哈希。只要发现新增、修改或删除，就将索引标记为 stale，阻止继续基于旧快照给出当前代码结论。”

5. **刷新与历史可追溯性（60–90 秒）**

   点击“刷新索引”，等待状态恢复为“当前证据可用”，创建新会话后重复问题。

   “刷新创建的是新的集合，不覆盖旧集合。旧会话仍指向历史快照，新的会话才绑定新快照，因此证据版本始终明确。点开旧证据还能看到它因历史会话而被保留的原因；空间回收也只允许删除未被引用的旧快照。”

6. **收束（30 秒）**

   “这不是一个会修改代码的自治 Agent。修复建议会经过证据校验后以可审查的补丁预览返回，不会直接应用。”

## 常见追问

| 追问 | 回答要点 |
| --- | --- |
| 为什么不直接每次读文件？ | 文件读取无法进行语义检索；向量检索提高定位效率，但必须绑定版本防止陈旧性。 |
| 为什么不用 Git commit 当版本？ | 允许未提交的本地修改；文件清单哈希更贴近用户真正看到的工作区。 |
| 如何避免泄露密钥？ | 只扫描授权根，过滤 `.env`、私钥、依赖和二进制，并限制工具读取范围。 |
| 为什么不让 Agent 自动修复？ | 自动写入扩大权限和风险。先提供证据与补丁预览，让用户审核，是更可信的工程边界。 |
